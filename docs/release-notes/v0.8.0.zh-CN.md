# v0.8.0 开发线说明

`0.8.0` 开发线为已有归档条目增加可选的保留历史弹幕刷新。默认 `legacy` 更新策略继续兼容现有
XML 仅追加和 ASS 重新生成行为。

`0.8.0` 开发线还新增 `BiliClient::credential_account_identity` 账号身份查询 API，供嵌入式服务
核对登录或续期前后的账号。调用方可选择
Web Cookie、通用 access key 或 TV access key；前者通过官方 Web 身份接口检查，后两者通过签名
OAuth 身份接口检查。成功结果包含已验证的正数账号 ID 和凭据类型。未登录、
身份缺失或格式错误、接口拒绝均返回错误；健康检查不能证明账号身份。OAuth 查询不会转发 Web Cookie，
诊断信息不包含凭据或账号 ID。服务端仍负责同账号策略和凭据存储。旧通用 key 的签发方回退只会在
文档规定的拒绝码下进行，并共用一次请求超时预算。

## 重点

- 增加 `bbdown danmaku update --update-policy preserve` 和公开的
  `DanmakuUpdatePolicy::Preserve` 选项。
- 保留已有 XML 结构和字节，包括未知元素、属性、注释、文本与重复弹幕。去重优先使用正十进制
  弹幕 ID；ID 缺失、为零或无效时，回退到完整 `p` 值与解码后的文本。
- 每次根据合并后的完整 XML 重建生成的 ASS 旁路文件，并用 `generated_events` 单独报告生成事件数。
  没有 XML 基线时，以本次拉取的 XML 初始化生成文件；不会把仅存在于旧 ASS 中的历史弹幕补回。
- 将旁路文件和更新后的归档一起暂存。嵌入 API 在发布前提供不可变的预期内容和暂存输出，
  发布时再次校验内容与目标路径。检测到错误会尝试回滚；必要时报告保留的恢复文件位置。

## 限制

内容校验不会协调外部写入方。使用 File Provider 或其他同步文件系统的应用必须自行协调占位文件物化成实际文件的过程及并发写入。回滚处理可检测的失败，但不承诺
多个文件之间具有崩溃或断电原子性。
`Preserve` 策略为可选；现有脚本继续使用默认 legacy 行为和报告 JSON 形状。

CLI 和 API 详情见[用户指南](../user-guide.zh-CN.md)、[嵌入指南](../embedding.zh-CN.md)和
[架构指南](../architecture/rust-rewrite.zh-CN.md)。
