# v0.8.0 Source-Line Notes

`0.8.0` source line 为已有归档条目增加可选的 preserving danmaku 刷新。默认 `legacy` 更新策略
继续兼容现有 XML append 和 ASS regeneration 行为。

## 重点

- 增加 `bbdown danmaku update --update-policy preserve` 和 public
  `DanmakuUpdatePolicy::Preserve` 选项。
- 保留已有 XML 结构和字节，包括未知元素、属性、注释、文本与重复弹幕。去重优先使用正十进制
  comment ID；ID 缺失、为零或无效时，回退到完整 `p` 值与解码后的文本。
- 每次根据合并后的完整 XML 重建生成的 ASS 旁路文件，并用 `generated_events` 单独报告生成事件数。
  没有 XML 基线时，以本次拉取的 XML 初始化生成文件；不会把仅存在于旧 ASS 中的历史弹幕补回。
- 将旁路文件和更新后的 archive 一起暂存。嵌入 API 在发布前提供不可变的预期内容和暂存输出，
  发布时再次校验内容与目标路径。检测到错误会尝试回滚；必要时报告保留的恢复文件位置。

## 限制

内容校验不会协调外部写入方。使用 File Provider 或其他同步文件系统的应用必须自行协调
materialization 与并发写入。回滚处理可检测的失败，但不承诺多个文件之间具有崩溃或断电原子性。
Preserve 策略为可选；现有脚本继续使用默认 legacy 行为和报告 JSON 形状。

CLI 和 API 详情见[用户指南](../user-guide.zh-CN.md)、[嵌入指南](../embedding.zh-CN.md)和
[架构指南](../architecture/rust-rewrite.zh-CN.md)。
