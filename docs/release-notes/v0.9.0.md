# v0.9.0 Release Notes

The `0.9.0` source line adds structured CDN transfer diagnostics and signs personal-space dynamic
feed requests with WBI. It retains the compatibility policies and pagination behavior described
below; these additions do not imply automatic CDN routing or playback acceptance.

## Highlights

- Expose typed `DownloadProgressEvent::TransferBytesReceived` and
  `DownloadProgressEvent::TransferDiagnostic` events through `DownloadProgressSink`,
  `probe_media_cdns_with_progress`, and CLI `--progress-json`. Diagnostics describe candidate
  selection or exclusion, retry and whole-file fallback reasons, request phase and outcome, parsed
  host, and response-body bytes consumed by the application.
- Sign personal-space dynamic feed requests with the existing WBI key lookup and signer. Sign the
  complete initial and continuation-page query, including `offset`, while keeping the existing
  Following feed request behavior.

## Byte Semantics

`bytes_delta` is the amount consumed from one response body during an event; `bytes_received` is a
cumulative watermark for that request. Sum deltas for consumed-body totals and do not sum the
cumulative field again. These counts are distinct from bytes written or published to a file.
They follow transparent response decoding, may include partial, failed, retried, or cancelled
requests, and do not represent compressed entity octets or all wire traffic. A response rejected
before body consumption contributes zero.

## Limits

- A selected CDN candidate means sample, size, and path/query preflight found a compatible group; it
  does not prove full-representation identity. Diagnostics add no representation validator and do
  not change candidate compatibility.
- Production shard chunks remain fixed at 1 MiB. This line does not add adaptive chunk sizing,
  automatic routing, persistent route health, suffix resume, hedging, or throughput claims.
- Dynamic feed rows are metadata records. Their count does not establish how many items can be
  played or downloaded.
