# v0.6.0 Release Notes

`v0.6.0` is a credential lifecycle release for `bbdown-core` and the `bbdown` CLI. It focuses on
making login state inspectable, refreshable where possible, and safer to update in multi-account
stores.

## Highlights

- Added versioned credential lifecycle metadata for profiles. Profiles can now record credential
  provenance, acquisition and check timestamps, expiry hints, provider metadata, and refresh-token
  presence without moving raw tokens into runtime `Credentials`.
- Added profile-level lifecycle status and health policy APIs. Embedders can evaluate whether a
  selected or named profile is fresh, stale, expiring, expired, unknown, missing, or ready for
  renewal before planning or downloading.
- Expanded CLI status and health UX. `auth status --profiles`, `auth status --all-profiles`, and
  `auth health --all-profiles` expose selected/default profile markers, redacted lifecycle
  summaries, network health probes, and guidance without printing raw credentials.
- Added explicit `auth renew-access-key` orchestration. Fresh credentials return `no_action`;
  stale, expired, or missing credentials can produce a reauthorization ticket or, when stored
  provider secrets are ready, attempt automatic refresh. `--force` always selects reauthorization
  for a present credential and does not use the stored refresh secret.
- Added explicit `auth renew-web` and `auth renew-tv` flows for stored WEB cookies and TV access
  keys. Credential preflight can automatically refresh these slots when their refresh metadata is
  ready; refresh failures preserve the existing credentials and report the failure.
- Added provider-aware plaintext refresh-secret storage. Refresh secrets live under
  `profile_secrets.<profile>.access_key.<provider>` while runtime `Credentials` stay limited to
  cookie, generic `access_key`, and TV `tv_access_key` values.
- Added provider-specific access-key refresh clients for Bilibili main OAuth2 and BiliIntl OAuth2,
  including TV OAuth refresh routing for `bili_tv` keypairs. Transient refresh failures preserve the
  existing token. The direct `auth renew-access-key` CLI orchestration turns a failed automatic
  refresh into a reauthorization ticket; lower-level client and preflight callers do not provide
  that CLI fallback.
- Added optional credential preflight for `plan`, `playback`, and `download` through
  `--credential-preflight off|warn|fail|renew`. Core callers can use `CredentialPreflightReport`
  directly for fixed request-path contexts.
- Added incremental profile update APIs and a cooperative credential-store lock so selected-profile
  refreshes, imports, and reauthorizations do not overwrite unrelated profiles or concurrently
  refreshed credentials.
- Added persistent default-account switching through `auth switch <profile>` and
  `CredentialStore::set_default_profile`. The CLI command changes the stored default profile, while
  `--credential-profile <name>` remains a one-command override.
- Added an explicit API for resolving a normal BV video's UGC collection or series membership from
  `ugc_season` metadata. The returned reference exposes stable collection metadata and can be sent
  through the existing paginated space collection/series resolver; ordinary BV input and download
  planning remain single-video operations by default.

## CLI Notes

- Use `bbdown auth status --profiles` for local lifecycle summaries and `bbdown auth health
  --all-profiles` when network-backed credential probes are appropriate.
- Use `bbdown auth renew-access-key --json` for machine-readable renewal decisions. JSON output uses
  newline-delimited events such as `decision`, `refresh_failed`, `ticket`, and `saved`.
- Use `bbdown auth switch <profile>` to persist the default profile for later commands; use
  `--credential-profile <name>` when an override should apply only to the current command.
- Use `--credential-preflight warn` to surface credential diagnostics without blocking a plan, and
  `--credential-preflight renew` to attempt provider-specific access-key refresh before media
  resolution when the selected profile is refresh-ready. For `download --archive-file ...`, the
  CLI may first resolve metadata or playurl data with the current credentials, then complete
  deferred renewal and replan; this mode does not guarantee refresh before that first resolution.
- Plaintext credential files still contain secrets. Keep them in user-private locations and avoid
  copying them into logs, issue comments, or release artifacts.

## Embedding Notes

- Use `CredentialProfiles::profile_lifecycle_status`, `lifecycle_statuses`, and
  `CredentialLifecyclePolicy` for local status screens before making network requests.
- Use `AccessKeyRenewalDecision` to decide whether automatic refresh is ready, whether explicit
  reauthorization is required, and why refresh is unavailable.
- Use `BiliClient::refresh_access_key(...)` when an embedder wants provider-specific refresh without
  shelling out to the CLI.
- Use `CredentialPreflightReport::from_client_context(...)` for conservative client-wide checks.
  Use `from_media_paths_context(...)` or `from_media_request_context(...)` when modeling the
  path-specific requirements of a downstream flow.
- Prefer `CredentialStore::update_profile` or `update_selected_profile` for credential mutations so
  embedders preserve other profiles and cooperate with concurrent writers.
- Use `CredentialStore::set_default_profile(...)` when an embedder needs to persist the selected
  default account; keep per-request choices separate from that stored default.
- Use `BiliClient::resolve_video_collection_membership(...)` when an embedder needs to inspect a
  video's collection or series without changing ordinary BV resolution. Pass the returned
  `UgcCollectionReference` to `BiliClient::resolve_video_collection(...)` to reuse the existing
  ordered collection/series resolution path.

## Compatibility

`bbdown-core` remains a pre-`1.0` crate. This release adds public credential lifecycle and preflight
surface area, JSON fields, and CLI events. Embedding projects should continue to construct
configuration through `Default`, `new`, and `with_*` methods, and should match non-exhaustive enums
or events with a wildcard arm where applicable.

## Release-Prep Validation

The release-prep PR validated the new release surface with:

- `cargo test -p bbdown-core --test public_api --locked`: passed.
- `cargo doc --no-deps -p bbdown-core --locked`: passed.
- Project journal validation: passed.
- Release archive smoke packaging: passed; the archive includes `docs/release-notes/README.md`,
  `README.zh-CN.md`, `v0.6.0.md`, and `v0.6.0.zh-CN.md`.
- `just ci`: passed, including formatter, clippy, Rust 1.95 check, workspace tests, mock CLI e2e,
  and `bbdown-core` publish dry-run for `0.6.0`.
- `just live-e2e`: attempted with the ignored local manifest. The run failed on restricted
  `pgc-hk-mo-tw` because every configured restricted-area proxy candidate returned `502 Bad
  Gateway` while the manifest expected an API-code proxy diagnostic. Treat this as an upstream
  proxy/fixture caveat, not as a deterministic release gate failure.
