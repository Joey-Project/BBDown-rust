# v0.3.0 Release Notes

Published on June 15, 2026, `v0.3.0` is the feed/list parsing release. It moves several Bilibili
page families onto a shared collection resolver so `info`, `plan`, `playback`, and `download` can
reuse the same selection and normal-video planning paths.

## Highlights

- Added a shared feed/list resolver abstraction for list-like Bilibili page families.
- Added authenticated history parsing for normal-video `archive` history records.
- Added authenticated following feed parsing and space dynamic video feed parsing.
- Added homepage recommendation parsing through the WBI recommendation endpoint.
- Added authenticated watch-later parsing through the WEB toview endpoint.
- Reused existing collection selection semantics across the new inputs: all/default, latest, page,
  and index/range selection.
- Kept selected feed/list items mapped back through normal video planning so stream, subtitle,
  danmaku, cover, playback, and download behavior stays consistent.

## CLI Notes

- New input shorthands include `history`, `following`, `recommendations`, `recommend`, `watchlater`,
  `watch-later`, `watch_later`, `later`, and `toview`.
- Supported URLs include Bilibili history, dynamic/following pages, homepage recommendations, and
  watch-later/list URLs.
- History, following/dynamic, and watch-later require a WEB cookie. Recommendation parsing uses
  public WBI endpoint behavior.
- Non-video feed cards are skipped until their item families have dedicated planning support.

## Embedding Notes

- The shared feed/list resolver keeps the public output shape as `ResolvedContent::Collection`.
- Feed/list item deduplication and one-based renumbering are handled before selected items are
  mapped back to normal video planning.
- Explicit index/range selection can stop pagination once the maximum requested index is covered.

## Compatibility

`v0.3.0` adds new input families and collection kinds. Embedders should use non-exhaustive matching
patterns or serde-compatible consumers where possible.
