# v0.11.0 Source Preparation Notes

This document records the `0.11.0` source-preparation state on 2026-10-20; it is not a publication
announcement. `0.10.0` is the latest published release as of that date. See the
[official GitHub Releases](https://github.com/Joey-Project/BBDown-rust/releases) page for current
publication status.

## Highlights

- Preserve domestic PGC main and supplementary episode groups in season metadata and CLI output.
  The existing flat episode list, selection indexes, and main-episode-only `Latest` behavior remain
  available. Rust callers constructing `SeasonMetadata` literals must provide the new
  `episode_groups` field; older JSON without it deserializes to an empty list.
- Add one-page ordinary-video keyword search with page and order selection. Search results remain
  metadata until the caller explicitly selects rows in the existing UGC/PGC flow. Search is not a
  generic automatic download listing, and selected PGC recognition requires the supported official
  episode redirect plus matching season metadata.
- Add anonymous anime and Chinese-animation timetable metadata, including the separate latest block,
  ordered days, episode identity, and publication/delay fields. This does not add generic inputs or
  download behavior.
- Add anonymous PGC movie and TV category-index pages and their filter/order choices. Listings remain
  metadata-only; they do not hydrate seasons, add generic inputs, or start planning or downloads.
- Add one-page anonymous popular-video metadata through `bbdown popular` and
  `BiliClient::popular_videos`.
- Add anonymous global ranking metadata through `bbdown ranking` and
  `BiliClient::ranking_videos`. It requests public WBI keys from `/x/web-interface/nav`, then sends
  the signed ranking query with `rid=0`, `type=all`, and `web_location=333.934`. Missing or blank
  BVIDs remain absent; the client does not impose a raw-row cap.

## API Boundaries And Limits

- Search fetches one page, accepts at most 20 raw rows, caps each response at 1 MiB, and makes at
  most two anonymous API requests for navigation and search. Keywords must be 1–200 UTF-8 bytes and
  contain no control characters. Supported orders are `totalrank`, `click`, `pubdate`, `dm`,
  `stow`, and `scores`. Search metadata uses `api_base`; selected-row PGC metadata uses `pgc_base`.
- The timetable makes one anonymous request through `pgc_base`, caps the JSON response at 1 MiB,
  and limits decoded data to 32 day groups and 4096 aggregate raw rows.
- Movie and TV index requests use `pgc_base`, fetch one page per call, and cap each response at
  1 MiB. Page numbers must be positive and page size is 1–20. Filter values are non-empty, contain
  no control characters, and are limited to 256 UTF-8 bytes. Filter choices are returned as source
  metadata; category identifiers are not inferred.
- Popular-video requests use `api_base`, fetch one page per call, use a 1 MiB response cap, and
  accept page sizes from 1 to 20. Continuation comes from the upstream `no_more` field; the endpoint
  does not provide a total.
- Ranking uses `api_base` for both navigation and ranking requests. The default response cap is
  1 MiB per response. `RankingVideoOptions.max_response_bytes` and `--max-response-bytes` apply the
  same positive cap separately to each response; zero is rejected before HTTP. Ranking returns all
  valid rows in source order and has no added raw-row cap.
- Search, timetable, PGC index, popular, and ranking metadata routes have endpoint-specific
  capabilities. `api_base` and `pgc_base` are distinct, and `PgcWebPlayurlRoute` controls PGC Web
  playurl only. Configuring a gateway or playurl route does not promise support for unrelated
  metadata endpoints or universal regional access.
- These APIs enumerate metadata; they do not promise playback or media availability. Popular and
  ranking responses can change between calls, and separate calls do not share a stable snapshot.
- `Input::VideoSearch` and `VideoCollectionKind::Search` are new public enum variants, so downstream
  exhaustive matches must handle them. Existing callers constructing `SeasonMetadata` literals
  must add `episode_groups` as described above.
