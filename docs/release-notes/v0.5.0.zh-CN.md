# v0.5.0 版本说明

`v0.5.0` 是 `bbdown-core` 和 `bbdown` CLI 的 downloader / embedding polish 版本。重点是更
适合长任务集成、更清晰的媒体旁路文件选择，以及更丰富的 mux metadata。

## 重点

- 通过 `DownloadProgressEvent` 和 `*_with_progress` API family 增加 typed download progress
  callback。
- 增加成功、失败和取消的 terminal progress events。CLI `--progress-json` 现在有明确的 JSON
  Lines schema，便于下游 UI 不解析人类输出也能消费进度。
- 增加 cancellation-aware execution：`DownloadCancellationToken`、CLI `Ctrl-C` graceful
  cancellation、retry-backoff cancellation 检查、部分文件回滚，以及 cancellation-aware mux
  status 映射。
- 增加 `DownloadReport::summary()` helper，嵌入方可以直接展示 entry 数、文件数、mux 数和
  byte totals，不需要重新遍历每个 report entry。
- 增加章节 metadata mux 支持。Plan entry 会暴露发现的 `ChapterTrack`，ffmpeg mux 可以通过
  临时 ffmetadata 写入章节，并在 `MuxReport::chapter_count` 中记录写入数量。
- 增加音频语言 metadata 和选择。Plan 与 playback request spec 会暴露可选语言字段；
  `StreamSelection::audio_language(...)` / CLI `--audio-language` 可以选择首选音轨，并让
  archive key 区分不同显式选择。
- 增加 AI 字幕 metadata 和筛选。Plan 会保留 `SubtitleTrack::is_ai_generated`、`ai_type`
  和 `ai_status`；`SubtitleAiPolicy` / CLI `--subtitle-ai` 可选择包含、优先非 AI、排除或只
  下载 AI 生成字幕。
- 增加 repo-local live e2e fixture skill，并对齐 normal、multi-page 和 restricted-area
  Bilibili 回归样例 manifest。

## CLI 说明

- 外部 supervisor 需要机器可读进度时使用 `--progress-json`。把 `plan_completed`、
  `plan_failed` 和 `plan_cancelled` 视为互斥的 task terminal states。
- 使用 `--audio-language <language-or-display-name>` 可按 `language` 或 `language_doc` 首选
  DASH 音频语言。
- 下载字幕时配合 `--subtitle-ai include|prefer-non-ai|exclude-ai|only-ai` 控制是否写出 AI
  生成字幕。
- `Ctrl-C` 会请求 graceful cancellation。新创建的部分文件会被删除；续传文件会截断回本次
  尝试前的大小；已经完成的 entry 保持有效。

## 嵌入说明

- 优先使用 embedding guide 里的 builder 风格 API：
  `DownloadOptions::new(...).with_*`、`StreamSelection::audio_language(...)`、
  `DownloadCancellationToken::new()` 和 `DownloadOptions::with_subtitle_ai_policy(...)`。
- 当任务 UI 有用户取消状态时，用 `Error::is_cancelled()` 单独区分取消和普通失败。
- UI 摘要优先使用 `DownloadReport::summary()`；只有需要 per-file detail 的页面再读取
  `entries`。
- 匹配 progress events 时保留 wildcard arm。`DownloadProgressEvent` 是 `#[non_exhaustive]`，
  未来版本可能增加事件变体。

## 兼容性

`bbdown-core` 仍然是 pre-`1.0` crate。本版本新增了公开 API surface 和输出字段。嵌入项目
应避免用结构体字面量构造 `DownloadEntry` 等输出结构体；应消费返回值或 serde 输出。配置
应使用 constructors 和 `with_*` 方法，这样新增字段时更容易吸收。

## Release-Prep 验证

release-prep PR 已用以下 gate 验证新的 release surface：

- `cargo test -p bbdown-core --test public_api --locked`：通过。
- `cargo doc --no-deps -p bbdown-core --locked`：通过。
- `just ci`：通过，覆盖 formatter、clippy、Rust 1.95 check、workspace tests、mock CLI e2e
  和 `bbdown-core` publish dry-run。
- `just live-e2e`：已用被忽略的本地 manifest 尝试。deterministic public checks 没有报告回
  归，但 manifest run 在 restricted `pgc-hk-mo-tw` case 失败，因为所有配置的 restricted-area
  proxy 候选都返回 `502 Bad Gateway`，而 manifest 期望 API-code proxy diagnostic。这里按
  上游 proxy/fixture caveat 处理，不视为 deterministic release gate failure。
