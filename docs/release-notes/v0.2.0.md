# v0.2.0 Release Notes

Published on June 14, 2026, `v0.2.0` is a broad BBDown parity and playback integration release. It
adds more input families, richer sidecar controls, single-output downloads, and the first stable
request-spec surface for downstream playback/cache services.

## Highlights

- Added PUGV/cheese, B23 short links, space uploads, favorites, collections, and series inputs,
  including batch collection metadata and selection behavior.
- Added cover sidecar downloads and `--no-cover`.
- Added single-output download modes through `DownloadMode` and CLI `--only
  video|audio|subtitle|danmaku|cover`.
- Added ASS danmaku sidecar generation while keeping XML as the canonical default.
- Added UPOS host replacement and PCDN controls through `MediaHostOptions`, CLI `--upos-host`,
  `--force-replace-host`, and `--allow-pcdn`.
- Added output path templates for output root, entry directory, and mux file stem.
- Added structured index/range selection for pages, episode indexes, and batch collection items.
- Added `bbdown playback` and `BiliClient::plan_playback` with selected media request specs,
  headers, backup URLs, mime/codec metadata, duration/size, and cache keys.
- Added AVPlayer-oriented selection hints with configurable codec preference order.
- Added ABR/cache metadata for downstream bitrate switching and disk cache retention.
- Added TV HTTP playurl mode and APP gRPC playurl mode.

## CLI Notes

- Use `--select` with values such as `1`, `1,3-5`, `latest`, `all`, `page:<index>`, or
  `episode:<epid>` depending on the input family.
- Use `--only` when a caller wants one media or sidecar family without performing a full download.
- Use `--danmaku-format xml,ass` to write both canonical XML and generated ASS.
- Use `bbdown playback` for downstream player/cache integrations that need stable HTTP request
  specs instead of downloaded files.

## Embedding Notes

- `ResolvedContent::Collection` and collection planning are part of the public output surface in
  this line.
- `DownloadMode`, `DanmakuFormat`, `MediaHostOptions`, `DownloadPathTemplates`,
  `StreamSelection`, and playback planning types are available through `bbdown-core`.
- Playback planning intentionally stops at serializable request specs and metadata; player task
  state, HLS serving, cache retention, and runtime ABR policy stay downstream.

## Compatibility

`v0.2.0` adds new public output and configuration types after `v0.1.0`. Embedders should consume
returned values or serde output and prefer constructors/builders over struct literals.
