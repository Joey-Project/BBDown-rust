# v0.5.0 Release Notes

`v0.5.0` is a downloader and embedding polish release for `bbdown-core` and the `bbdown` CLI. It
focuses on long-running task integration, clearer media sidecar choices, and richer mux metadata.

## Highlights

- Added typed progress callbacks for download execution through `DownloadProgressEvent` and the
  `*_with_progress` API family.
- Added terminal progress events for successful, failed, and cancelled plans. CLI
  `--progress-json` now documents a JSON Lines schema that downstream UIs can consume without
  parsing human output.
- Added cancellation-aware execution with `DownloadCancellationToken`, graceful CLI `Ctrl-C`
  handling, retry-backoff cancellation checks, partial-file rollback, and cancellation-aware mux
  status mapping.
- Added `DownloadReport::summary()` helpers so embedders can display entry counts, file counts,
  mux counts, and byte totals without re-walking every report entry.
- Added chapter metadata mux support. Plan entries expose discovered `ChapterTrack` values, and
  ffmpeg muxing can pass them through temporary ffmetadata with `MuxReport::chapter_count`.
- Added audio language metadata and selection. Plans and playback request specs expose optional
  language fields, and `StreamSelection::audio_language(...)` / CLI `--audio-language` can choose
  preferred audio tracks while keeping archive keys distinct.
- Added AI subtitle metadata and filtering. Plans preserve `SubtitleTrack::is_ai_generated`,
  `ai_type`, and `ai_status`, while `SubtitleAiPolicy` / CLI `--subtitle-ai` can include, prefer
  non-AI, exclude, or select only AI-generated subtitle tracks.
- Added a repo-local live e2e fixture skill and aligned sample manifest entries for normal,
  multi-page, and restricted-area Bilibili regression checks.

## CLI Notes

- Use `--progress-json` when an external supervisor needs machine-readable progress. Treat
  `plan_completed`, `plan_failed`, and `plan_cancelled` as mutually exclusive terminal task states.
- Use `--audio-language <language-or-display-name>` to prefer a DASH audio language by `language`
  or `language_doc`.
- Use `--subtitle-ai include|prefer-non-ai|exclude-ai|only-ai` together with subtitle downloads to
  control whether AI-generated subtitle tracks are written.
- `Ctrl-C` requests graceful cancellation. Newly-created partial files are removed, resumed files
  are truncated back to their pre-attempt size, and completed entries remain valid.

## Embedding Notes

- Prefer the builder-style APIs already used in the embedding guide:
  `DownloadOptions::new(...).with_*`, `StreamSelection::audio_language(...)`,
  `DownloadCancellationToken::new()`, and `DownloadOptions::with_subtitle_ai_policy(...)`.
- Handle `Error::is_cancelled()` separately from ordinary failures when a task UI has a user
  cancel state.
- Use `DownloadReport::summary()` for UI summaries, then inspect `entries` only when a screen needs
  per-file detail.
- Match progress events with a wildcard arm. `DownloadProgressEvent` is `#[non_exhaustive]`, so
  future releases may add event variants.

## Compatibility

`bbdown-core` remains a pre-`1.0` crate. This release adds public API surface and output fields.
Embedding projects should avoid constructing output structs such as `DownloadEntry` with struct
literals; consume returned values or serde output instead. Configuration should use constructors
and `with_*` methods so added fields remain easier to absorb.

## Release-Prep Validation

The release-prep PR validated the new release surface with:

- `cargo test -p bbdown-core --locked v0_5_embedding_surface_is_reexported`: passed.
- `cargo doc --no-deps -p bbdown-core --locked`: passed.
- `just ci`: passed, including formatter, clippy, Rust 1.95 check, workspace tests, mock CLI e2e,
  and `bbdown-core` publish dry-run.
- `just live-e2e`: attempted with the ignored local manifest. The deterministic public checks did
  not report a regression, but the manifest run failed on the restricted `pgc-hk-mo-tw` case because
  every configured restricted-area proxy candidate returned `502 Bad Gateway` while the manifest
  expected an API-code proxy diagnostic. Treat this as an upstream proxy/fixture caveat, not as a
  deterministic release gate failure.
