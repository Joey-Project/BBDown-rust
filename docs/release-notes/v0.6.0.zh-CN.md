# v0.6.0 版本说明

`v0.6.0` 是 `bbdown-core` 和 `bbdown` CLI 的 credential lifecycle 版本。重点是让登录状态更
容易检查、在可行时刷新，并在多账号 credential store 中更安全地更新。

## 重点

- 增加 versioned credential lifecycle metadata。Profile 现在可以记录 credential provenance、
  acquisition/check timestamps、expiry hints、provider metadata 和 refresh-token presence，
  而不把 raw tokens 放进运行时 `Credentials`。
- 增加 profile-level lifecycle status 和 health policy API。嵌入方可以在规划或下载前评估
  selected/named profile 是否 fresh、stale、expiring、expired、unknown、missing 或可 renewal。
- 扩展 CLI status 和 health UX。`auth status --profiles`、`auth status --all-profiles` 和
  `auth health --all-profiles` 会暴露 selected/default profile markers、redacted lifecycle
  summaries、network health probes 和 guidance，不打印 raw credentials。
- 增加显式 `auth renew-access-key` 编排。Fresh credentials 返回 `no_action`；stale、expired、
  forced 或 missing credentials 会生成 reauthorization ticket，或者在 stored provider secrets
  ready 时尝试 automatic refresh。
- 增加 provider-aware 明文 refresh-secret 存储。Refresh secrets 存在
  `profile_secrets.<profile>.access_key.<provider>` 下；运行时 `Credentials` 仍只保存 cookie、
  generic `access_key` 和 TV `tv_access_key` 值。
- 增加 Bilibili main OAuth2 和 BiliIntl OAuth2 的 provider-specific access-key refresh
  clients，并为 `bili_tv` keypair 使用 TV OAuth refresh 路径。Transient refresh failures 会保留
  现有 token，并回退到显式 reauthorization。
- 为 `plan`、`playback` 和 `download` 增加可选 credential preflight：
  `--credential-preflight off|warn|fail|renew`。Core 调用方可以直接使用
  `CredentialPreflightReport` 表达固定 request-path contexts。
- 增加 incremental profile update API 和 cooperative credential-store lock，使 selected-profile
  refresh/import/reauthorization 不覆盖无关 profiles 或并发刷新的 credentials。

## CLI 说明

- 使用 `bbdown auth status --profiles` 查看本地 lifecycle 摘要；需要网络探测时使用
  `bbdown auth health --all-profiles`。
- 使用 `bbdown auth renew-access-key --json` 获取机器可读 renewal decisions。JSON 输出是
  newline-delimited events，例如 `decision`、`refresh_failed`、`ticket` 和 `saved`。
- 使用 `--credential-preflight warn` 显示 credential diagnostics 但不阻塞规划；使用
  `--credential-preflight renew` 在 selected profile refresh-ready 时，在媒体解析前尝试
  provider-specific access-key refresh。
- 明文 credential files 仍包含 secrets。请把它们放在用户私有位置，避免复制到日志、issue
  comments 或 release artifacts。

## 嵌入说明

- 使用 `CredentialProfiles::profile_lifecycle_status`、`lifecycle_statuses` 和
  `CredentialLifecyclePolicy` 在发起网络请求前构建本地状态界面。
- 使用 `AccessKeyRenewalDecision` 判断 automatic refresh 是否 ready、是否需要显式
  reauthorization，以及 refresh 不可用的原因。
- 嵌入方需要 provider-specific refresh 且不希望启动 CLI 时，使用
  `BiliClient::refresh_access_key(...)`。
- 使用 `CredentialPreflightReport::from_client_context(...)` 或
  `from_media_paths_context(...)` 表达下游流程会使用的精确 request paths。
- Credential mutation 优先使用 `CredentialStore::update_profile` 或
  `update_selected_profile`，以保留其他 profiles 并配合并发写入者。

## 兼容性

`bbdown-core` 仍是 pre-`1.0` crate。本版本新增公开 credential lifecycle 和 preflight
surface、JSON 字段以及 CLI events。嵌入项目应继续通过 `Default`、`new` 和 `with_*` 方法构造
配置，并在匹配 non-exhaustive enums/events 时保留 wildcard arm。
