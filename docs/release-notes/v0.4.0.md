# v0.4.0 Release Notes

Published on June 18, 2026, `v0.4.0` is the credential and danmaku maintenance release. It adds the
credential profile model, login/health surfaces, generic `access_key` acquisition, and archive-backed
append-only danmaku updates.

## Highlights

- Added unified QR login ticket/output surfaces for WEB and TV login flows.
- Added credential health diagnostics for WEB cookie, generic `access_key`, and TV `tv_access_key`
  credentials.
- Added multi-profile credential storage while preserving default-profile and legacy flat-file
  behavior.
- Added profile-aware credential selection in the CLI and embedding APIs.
- Added generic `access_key` acquisition through the BiliPlus authorization flow, including QR/link
  output and callback/message import.
- Hardened access-key import so terminal-backed interactive paste paths cannot echo sensitive tokens
  into scrollback.
- Added append-only danmaku update APIs and CLI workflow for already downloaded archive records.
- Added XML merge behavior that deduplicates comments and regenerates derived formats such as ASS
  while keeping XML as the canonical sidecar.

## CLI Notes

- Use auth/profile commands to import, select, inspect, and remove credential profiles.
- Use access-key login/import flows with explicit `--file` or `--stdin` input sources for sensitive
  callback data.
- Use `bbdown danmaku update <input> --archive-file <path>` to refresh danmaku sidecars for entries
  that already have archive records.
- Use repeatable or comma-delimited `--danmaku-format` values to regenerate selected derived
  formats during update.

## Embedding Notes

- `CredentialProfiles` preserve default-profile behavior while allowing named profiles.
- Health diagnostics return redacted credential probe status instead of leaking raw values.
- `BiliClient::update_danmaku_for_archive` updates matching archive entries by stable aid/cid
  identity and records refreshed sidecar paths back into the archive.
- Plan danmaku updates with `DownloadMode::DanmakuOnly` so update flows do not depend on media
  playurl availability.

## Compatibility

`v0.4.0` preserves legacy flat credential loading while adding profile documents. Credential and
danmaku update APIs are still pre-`1.0`; embedders should prefer constructors and helper methods over
direct struct construction.
