# v0.2.0 版本说明

`v0.2.0` 发布于 2026 年 6 月 14 日，是一次较大的 BBDown parity 和 playback integration
版本。它增加更多输入类型、更丰富的 sidecar controls、单独下载模式，以及给下游 playback/cache
服务使用的第一版稳定 request-spec surface。

## 重点

- 增加 PUGV/cheese、B23 短链、空间投稿、收藏夹、合集和系列输入，包括批量集合 metadata
  与 selection 行为。
- 增加封面 sidecar 下载和 `--no-cover`。
- 通过 `DownloadMode` 和 CLI `--only video|audio|subtitle|danmaku|cover` 增加单独下载模式。
- 增加 ASS 弹幕 sidecar 生成，同时保留 XML 作为 canonical default。
- 通过 `MediaHostOptions`、CLI `--upos-host`、`--force-replace-host` 和 `--allow-pcdn`
  增加 UPOS host replacement 与 PCDN controls。
- 增加 output root、entry directory 和 mux file stem 的路径模板。
- 增加 page、episode index 和 batch collection item 的结构化 index/range selection。
- 增加 `bbdown playback` 和 `BiliClient::plan_playback`，返回 selected media request specs、
  headers、backup URLs、mime/codec metadata、duration/size 和 cache keys。
- 增加面向 AVPlayer 的 selection hints，并允许配置 codec preference order。
- 增加 ABR/cache metadata，供下游做 bitrate switching 和磁盘缓存保留。
- 增加 TV HTTP playurl mode 和 APP gRPC playurl mode。

## CLI 说明

- 根据输入类型使用 `--select`，例如 `1`、`1,3-5`、`latest`、`all`、`page:<index>` 或
  `episode:<epid>`。
- 调用方只需要某一类 media 或 sidecar 时使用 `--only`，避免完整下载。
- 使用 `--danmaku-format xml,ass` 同时写出 canonical XML 和生成的 ASS。
- 下游播放器/缓存集成需要稳定 HTTP request specs 而不是下载文件时，使用 `bbdown playback`。

## 嵌入说明

- `ResolvedContent::Collection` 和 collection planning 是这一版本线的公开输出 surface。
- `DownloadMode`、`DanmakuFormat`、`MediaHostOptions`、`DownloadPathTemplates`、
  `StreamSelection` 和 playback planning types 通过 `bbdown-core` 暴露。
- Playback planning 只负责 serializable request specs 和 metadata；player task state、HLS
  serving、cache retention 和 runtime ABR policy 仍由下游实现。

## 兼容性

`v0.2.0` 在 `v0.1.0` 之后增加了新的公开输出和配置类型。嵌入方应消费返回值或 serde 输出，
并优先使用 constructors/builders，避免结构体字面量。
