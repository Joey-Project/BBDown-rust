# v0.7.0 Release Notes

`v0.7.0` is the networking and downloader release line for the Rust rewrite. It adds explicit,
opt-in CDN controls for resolved media downloads and an independent PGC Web playurl route API.
Bundled catalogs provide candidates to inspect or select; they do not create an automatic routing
policy.

## Highlights

- Add repeatable `--cdn-host` selection and `MediaHostOptions::with_cdn_hosts` for an ordered host
  pool. The existing `--upos-host` behavior remains a separate manual host override.
- Add optional `--cdn-probe` and `probe_media_cdns(...)` Range measurements. Probes consider at most
  eight candidates and read at most 64 KiB per candidate, including the bounded size-discovery byte
  when the media size is unknown. A probe sends real requests only when explicitly run; a probe
  ranking does not guarantee that a signed URL works on another host.
- Add optional parallel Range transfer. CLI `--cdn-parallel` defaults to 1 (disabled) and accepts
  2 through 8. Parallel transfer requires compatible range responses and a consistent total length.
  Multi-host sharding further requires candidate URLs with the same scheme, path, query, and initial
  byte sample. Failed chunks can retry through another candidate, and recoverable failures use the
  regular download path. Matching size and prefix do not prove that later bytes from different hosts
  are identical, and parallel transfer does not guarantee a speedup.
- Bundle a regional CDN host snapshot and a historical public resolver catalog. `bbdown cdn list`,
  `bbdown cdn probe`, and `bbdown resolver list` expose their contents. Users explicitly choose a
  preset or resolver; catalog entries are not availability guarantees. Runtime probe and download
  requests go to the selected hosts only when the corresponding command or option is used.
- Add `PgcWebPlayurlRoute` and `ClientConfig::with_pgc_web_playurl_route(...)` for PGC Web playurl
  planning. The default `OfficialThenProxy` preserves the configured region-error fallback;
  `OfficialOnly` skips proxy fallback, and `ProxyOnly(proxy)` targets the selected proxy. This route
  setting does not change PGC metadata or TV/APP playurl requests. A selected proxy may receive the
  episode and area request data and, where configured, the generic access key; the Web cookie is
  not sent to that proxy.

## Validation and Limits

Local HTTP mocks cover catalog selection, CDN probe and transfer behavior, and restricted PGC
API-path routing without public network requests or credentials. Optional live checks are separate:
the CDN benchmark makes public video requests without credentials, while restricted PGC live
validation uses the user's locally configured Web cookie and generic access key with the explicitly
selected endpoints. Do not put those credentials in reports or artifacts.

The controlled CDN comparison covered two representation sizes in two short morning windows, with
18 successful downloads. Results varied by host, size, and time and did not establish a stable
speedup, an all-day or multi-location performance distribution, or a default route policy. Output
hashes compare completed samples; they do not establish content identity for every CDN edge. Shard
byte reports describe published output bytes, not total wire traffic. Candidate-exclusion reasons,
cross-candidate retry diagnostics, and HTTP response-body byte totals remain deferred, as do
automatic routing, persistent route health, and adaptive policy. Even response-body totals would not
represent all wire traffic.

## Embedding and Compatibility

`bbdown-core` remains pre-1.0. This release adds public configuration and API surface; downstream
source compatibility is not guaranteed across releases. Prefer `Default`, `new`, and `with_*`
constructors instead of public struct literals, and consume output structs as returned values or
through serde. `PgcWebPlayurlRoute` and related public enums are non-exhaustive; retain wildcard
match arms. The route API affects PGC Web playurl planning only and does not race requests in the
background; applications that need to compare official and proxy results must create and coordinate
their requests explicitly.
