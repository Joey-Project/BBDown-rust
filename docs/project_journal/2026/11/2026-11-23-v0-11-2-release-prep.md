# v0.11.2 Release Preparation

## Summary

- Fix FFmpeg container selection for staged output and add selectable Matroska output in `0.11.2`.
- This journal records source preparation only. RC/tag creation, publication, and release validation
  remain separate gates.

## Included Changes

- FFmpeg explicitly receives the selected output muxer after the input options. The staged file
  uses the same container as the final file, and is moved into place after muxing succeeds.
- The CLI accepts `--mux-format mp4|mkv`. Embedded callers can set `DownloadOptions::with_mux_format`
  when opting into FFmpeg. Existing calls default to MP4.
- Download archives keep the existing MP4 keys and give MKV a distinct format key.

## Local Validation

- The mux test asserts that the output format follows the inputs and precedes the staging path.
  Real FFmpeg 8.1.1 regressions used local synthetic media to verify DASH-to-MP4 and FLV
  concatenation-to-Matroska through the core downloader.
- Formatting, strict Clippy, the Rust 1.95 workspace check, and workspace tests passed. The workspace
  ran 1,069 passing tests with four ignored. The separate 215 CLI e2e tests overlap that count.
- The publish dry run verified `bbdown-core v0.11.2` with 45 packaged files. Cargo reported the
  existing `spin 0.9.8` yank warning.
- An anonymous local `bbdown 0.11.2` live download of Bilibili documentary `ep318903` produced MP4
  and Matroska outputs. `ffprobe` verified HEVC video, AAC audio, and 590.46 seconds in both.
  Both completed without leftover mux staging files.
